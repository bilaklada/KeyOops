# 002 · Contextual live correction

Live mode uses Accessibility to read committed text from a focused writable single-line or multiline text control. Keyboard events trigger checks without decoding the typed characters. A 24 ms coalescing interval gives the host time to insert text. The model and dictionaries load away from the main thread.

On whitespace, the decoder compares the typed and physical-key readings of each word. A forward and backward pass computes the best complete sequence under each reading at each position. The difference is the confidence margin. Scores combine bilingual KenLM probabilities, dictionary evidence, and a layout-state prior trained on simulated slips. Automatic mode commits high-margin words and keeps unresolved neighbors available for later evidence. Unseen target names can accompany a supported run for review.

The active window contains at most 16 words. When it fills, the oldest eight decisions are frozen and the recent words retain their left context. Sentence punctuation and line breaks restart lexical scoring with a unigram. Weaker evidence about the intended language and keyboard state carries across that boundary, so the next sentence can clarify an earlier word. Double whitespace and unsupported tokens start a fresh fragment. Suggestions from completed fragments stay in one batch. At 4,096 UTF-16 units, a pending batch freezes until accepted or dismissed. The caret may advance beyond it without retaining the additional text.

One session belongs to one app process, window, field and document. Web controls bind every ancestor web document element and URL along with the field and focused window. The app subscribes to focus notifications, document loads and destruction. Native controls require an identifiable document or a resolvable host text marker; TextEdit's unsaved document window supplies its identity. Terminal and password-manager bundle exclusions are checked before field inspection. Secure Input, protected control ancestry and unreadable or read-only controls prevent binding. Accessibility editing is the only live replacement path. Browser chrome outside a verifiable web document is excluded for recognized browsers. Focus notifications, app activation, sleep, navigation and editing commands invalidate the binding. Append checks verify the original text, caret, and the length and beginning of the text to its right. A replacement rechecks ownership, exact source text and temporary selection immediately before writing. A successful edit can switch the active input source and supplies a guarded inverse edit. Dismissal and undo advance the lower bound of future inspection.

The selection Service continues to operate independently of live sessions.
